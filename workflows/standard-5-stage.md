# 标准 5 阶段编排流程

> 从"一句话想法"到"可交付代码"的完整产研流水线。

## 阶段全景图

```
一句话想法
    ↓
[阶段 1] 🎯 PM
    ↓ 输出：PRD（含 AC）
[阶段 2] 🏗️ 架构师
    ↓ 输出：技术方案 + API 契约 + Prompt（如需）
[阶段 3] 🎨 前端 ⚙️ 后端（并行）
    ↓ 输出：可运行代码
[阶段 4] 🧪 QA
    ↓ 输出：测试用例 + Bug 报告 + 放行决策
[阶段 5] 🚀 DevOps（如需部署）
    ↓ 输出：部署脚本 + launchd/CI 配置
可交付
```

---

## 何时用完整 5 阶段，何时能跳过？

| 项目类型 | 建议流程 |
|---|---|
| 复杂 Web/插件（含 UI） | 完整 5 阶段 |
| 纯脚本 / 定时 bot | 🎯 PM → 🏗️ 架构师 → ⚙️ 后端 → 🧪 QA → 🚀 DevOps（跳过前端） |
| 快速原型 / MVP | 🎯 PM → ⚙️ 后端（架构师和 QA 可选） |
| Agent Skill / prompt 库 | 🎯 PM → 🏗️ 架构师（Prompt 模式）→ 🧪 QA |
| 数据分析 / 报表 | 直接 📊 数据分析师 |

---

## 阶段 1：PM 产出 PRD

**触发**：用户丢来一句话想法，或粘一段模糊需求。

**调用**：
```
@🎯 PM 帮我写 PRD：{一句话}
```

**PM 会问什么**（一次最多 5 个真正影响决策的问题）：
- 输入是什么？（数据源 / 触发时机）
- 输出是什么？（去哪 / 给谁看）
- 有没有已存在的东西可以复用？
- 特殊约束？（权限 / 网络 / 隐私）
- 归属谁维护？

**PM 不会问**：目标用户、成功指标、上线时间 —— 对内部工具场景经常不适用。

**产出**：结构化 PRD（9 个章节）+ 明确交接指令。

---

## 阶段 2：架构师技术方案

**触发**：PRD 完成后。

**调用**：
```
@🏗️ 架构师 基于这份 PRD 出技术方案
```

**架构师会输出**：
- 模块拆分（3-5 个）
- 数据模型（TypeScript / SQL / JSON schema）
- API 契约（前端要调什么接口）
- 技术选型（+ 选型理由）
- 边界与风险
- 涉及 LLM 时**同时输出 Prompt** + 验收 checklist

**关键**：架构师产出的 **API 契约 + Mock 数据**让前端能立刻并行开工，无需等后端。

---

## 阶段 3：前后端并行开工

**触发**：架构师方案定稿后。

**并行调用**（在两个不同的 topic 里）：
```
Topic A: @🎨 前端 按这份方案实现前端
Topic B: @⚙️ 后端 按这份方案实现后端
```

**前端会输出**：
- 文件结构树
- 逐文件完整代码（禁止 `// ... 省略`）
- 本地运行 3 步命令
- 与后端联调 checklist

**后端会输出**：
- API/数据契约（如架构师未定，后端补一份）
- 逐文件完整代码
- 单测（Vitest）
- curl / 用法示例
- 环境变量清单

**同步节奏**：
- 前端遇到 API 契约不清 → 反馈编排者 → 编排者去问架构师或后端
- 后端契约有变 → 通知前端

---

## 阶段 4：QA 验收

**触发**：前后端代码都交付后。

**调用**：
```
@🧪 QA 验收这个项目：{PRD 链接} + {代码位置}
```

**QA 会分阶段**：
1. **测试用例设计**（早在编码前就可以做）
2. **执行测试**：用 lobe-cloud-sandbox / lobe-browser 跑
3. **Bug 报告 + 放行决策**：✅ 通过 / ⚠️ 有条件通过 / 🚫 阻塞

**QA 三个附加模式**（同一 agent）：
- `@🧪 QA 安全审计一下` → 切安全模式（SQL 注入 / XSS / 密钥泄漏 / 依赖投毒）
- `@🧪 QA 剖析下性能` → 切性能模式（LCP / SQL / 内存）
- `@🧪 QA 验收 / 放行` → 切验收模式（默认）

---

## 阶段 5：DevOps 部署（如需）

**触发**：QA 放行后，需要真实部署（launchd / CI / Docker）时。

**调用**：
```
@🚀 DevOps 给这个脚本写 launchd plist，每天 10:45 跑
```

**DevOps 会输出**：
- 完整可运行代码
- 验证步骤
- 失败告警接入点（飞书/邮件/Slack 机器人）
- 回滚 / 卸载方式

---

## 编排小贴士

### 用主对话做「项目经理」，subagent 做「专家」
不要让 5 个 agent 互相直接对话（容易失控）。你（或主对话 AI）作为项目经理，逐个调用 agent，把上一阶段的输出粘给下一阶段。

### 保留每阶段产物
每个阶段的产物（PRD / 技术方案 / 代码 / 测试报告）都存进项目档案（可以用 `lobe-agent-documents` 或本地 Markdown）。方便下次迭代直接接续。

### 循环回炉是正常的
- QA 发现 P0 → 回炉给前端/后端
- 架构师方案不通 → 回炉给 PM 澄清
- PM 需求变了 → 全部重来（或增量迭代）

### 一个 topic 一个阶段
不要在同一个 topic 里让 PM 和后端讨论。每个阶段开新 topic，清爽可追溯。

---

## 与 extra-2 / optional-3 的配合

- **📊 数据分析师**：需要设计指标、A/B 测试、报表时接入
- **🚀 DevOps**：需要部署上线时接入（阶段 5）
- **🔬 UX 研究员**：项目开工前的用研阶段（PM 之前）
- **🎯 品牌守护者**：涉及对外品牌资产的项目里接入（前端 UI 定稿后审）
- **📈 增长黑客**：C 端产品上线后接入（本流水线之外）
